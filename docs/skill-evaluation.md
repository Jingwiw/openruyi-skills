# 技能评测

## 优先级

1. **安全边界合适且任务结果达标。** 核实环境、索取必要输入、遵守操作授权获得正向评价。无根据地拒绝可完成的工作、猜测身份或越权执行均记录为缺陷。
2. **达到上述条件后比较完成时间。** 包括实际返工；等待用户输入单独记录，保留其合理性。
3. **再比较真实模型 token 用量。** 分别报告 input、cached input、output；reasoning 若属于 output 子集不重复相加。字节和字符仅描述材料大小。

保留各维度，不把安全缺陷用“省时、省 token”抵消。结果不达标的运行不能赢得效率比较。

## 对照设计

- 用相同任务、fixture、模型和执行限制，分别提供现有/聚焦触发条件的描述及其中英文版本。该轮只改变 description，保持名称、正文、参考资料一致。
- 每次使用无历史上下文的新 agent；先看 frontmatter，再选择正文。记录实际选择与读取，不要求固定数量的技能。
- 增加无自定义技能对照，观察技能是否真的改善任务。评测材料为模拟数据，不能写成真实构建或安装结果。
- 预先保存任务、验收准则及内容哈希。评分者只看任务和匿名交付，不看描述语言/版本标签。
- 对具体缺陷发起实际修订，记录追加用量与时间；最多两轮。必要的用户输入请求保持为正确边界，不计作返工。
- 小样本仅给出探索性结果；中文任务上的差异不能外推为所有语言、模型或技能的优劣。

第一轮三个任务：识别跨架构 OBS 旧产物；设计 PAM/D-Bus Docker 消费者实验；按模板起草简洁 PR。它们分别覆盖身份判断、实验设计与贡献表达。真实外部操作另做独立测试。

用 `python3 tools/prepare_eval.py --output NEW_DIRECTORY` 生成独立快照与校验值。将单个任务和单个变体提供给无历史上下文的 agent；评分者仅接收任务、rubric 和匿名交付。准备脚本不启动模型或远端操作。

本地 Codex 会话可用 `tools/collect_agent_metrics.py` 按指定父线程和 agent 前缀提取 task_complete 耗时及 token_count 计数。输出只含指标，不复制提示词或消息内容。其他执行框架使用其真实 usage 记录；缺失指标标为缺失。

## 研究依据与可检验改进

检索日期：2026-10-01。以下研究用于提出实验，不直接当作本库有效性的证明。

| 来源 | 本轮采用的检验 |
| --- | --- |
| [SkillsBench v4，2026-06-14](https://arxiv.org/abs/2602.12670v4) | 同任务有/无技能配对，观察聚焦技能的实际收益 |
| [SkillReducer v2，2026-06-24](https://arxiv.org/abs/2603.29919v2) | 将描述路由和正文组织分开优化；先测简短描述，再测按需参考，防止删掉有效约束 |
| [SWE-Skills-Bench，2026-03-16](https://arxiv.org/abs/2603.15401) | 将验收与具体任务绑定，记录 token 开销和指导与项目版本是否冲突 |
| [Evaluating AGENTS.md，2026-02-12](https://arxiv.org/abs/2602.11988) | 检查附加要求是否引发无用探索或测试，保留无技能对照 |
| [SkillSeek，2026-09-30](https://arxiv.org/abs/2609.38822v1) | 单独观察发现/选择成本，避免把全部技能正文注入；当前 16 项规模先测选择，不为此预建检索系统 |

后续优化一次只改一个因素：触发描述、正文去重、参考按需加载、脚本代替重复推理。每次复用保留集之外的新任务确认；训练或修订时见过的任务结果单独标注。
