# 下游补丁评估

从补丁要解决的行为开始，不从能否无冲突应用开始。绑定目标版本、补丁及原问题；阅读头部来源、上游提交或 issue。

- 在目标发布源码中检查相关实现和测试，确认修复是否已经存在；提交哈希不同不等于语义不同。
- 其他发行版的补丁提供候选原因，不是可直接套用的答案。比较版本、架构、构建选项与问题输入。
- 补丁无法应用可能因为上下文变动，也可能已上游合入；补丁能应用也可能重复或改变新行为。
- 若同版本改变一个受支持的配置选项即可解决，优先验证选项，不自动发明 backport。需要代码修复时保留来源、适用范围及测试证据。
- 删除补丁同时核对 SPEC 引用和实际功能；不要只删文件。保留补丁则检查其维护成本、上游状态和许可证来源。

交付逐个补丁的结论：保留 / 调整 / 删除 / 未确认，并附依据。修改和验证可由别的能力完成；无复现或语义依据不把“疑似合入”写成“已解决”。
